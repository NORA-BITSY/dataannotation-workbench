## Original practice exercises

Use blank notes and a timer. Start with the task and leave the key collapsed or below the fold until you finish. These original scenarios train the underlying skills. DataAnnotation controls the live assessment format and content.

### A. Generalist · 15 minutes

A customer asks for two bullets, at most 55 words total, explaining how to cancel a fictional boat-storage booking and what refund to expect. The policy says cancellations go through the account’s **Bookings** page. Cancellations at least 48 hours before arrival refund the full $80 storage fee. The $5 booking fee is always excluded. Inside 48 hours there is no refund. A customer cancels 52 hours before arrival.

- **Answer A** — “Call the marina or cancel from your dashboard. You’ll receive the full $85 because you’re outside the 48-hour window.”
- **Answer B** — “Open Bookings and cancel there. You’ll receive $80. The $5 booking fee is excluded, and 52 hours is before the cutoff.”

Rank A and B in two sentences. Name any instruction and factual violations. Then write the requested two-bullet customer answer. For a public-source practice variation, verify DataAnnotation’s government-ID requirements against its current FAQ and write a three-sentence explanation with one source link and no details beyond the source.

### B. Coding and backend · 35 minutes

Write `first_pair(values, target)` in Python. Return the index pair `(i, j)` where `i < j` and `values[i] + values[j] == target`. If several pairs exist, choose the smallest `j`, then the smallest `i`. Return `None` if none exists. Do not mutate the input. Target expected O(n) time. Explain the approach and give at least five test cases.

Review this candidate implementation before writing yours. Give a concrete counterexample for each defect you identify.

```python
def first_pair(values, target):
    seen = {}
    for j, value in enumerate(values):
        seen[value] = j
        complement = target - value
        if complement in seen:
            return seen[complement], j
    return None
```

Backend extension. A booking API checks whether an order exists, then writes it. Two identical requests with the same client idempotency key arrive together. Explain the race, specify where uniqueness must be enforced, and describe the response when the same key is reused with a different payload. Name a concurrency test you would run.

### C. FP&A, valuation, and credit · 25 minutes

1. **FP&A.** Budget was 1,000 units at $30. Actual was 900 at $33. Compute total revenue variance and a price/volume bridge. Use budget price for volume variance and actual units for price variance. Write a two-sentence management explanation without inventing a reason for the price or volume movement.
2. **Finance.** In a fictional company, forecast EBIT is $24m, the tax rate is 25%, D&A is $6m, capex is $10m, and operating net working capital rises from $12m to $17m. An AI answer adds the NWC increase to cash flow. Calculate FCFF and identify the direction and magnitude of the error. Assume year-one FCFF grows at 2% forever, WACC is 10%, debt is $30m, and excess cash is $8m. Calculate EV and equity value under that simplified single-stage setup. Flag at least two assumptions you would stress-test.
3. **Credit bonus.** If annual NOI is $720,000 and annual debt service is $600,000, calculate DSCR. Repeat after a 15% NOI decline and compare both with a 1.20× covenant minimum.

### D. DevOps and full stack · 15 minutes

An AI proposal deploys a service using `image: latest`, grants the CI runner owner permissions, merges after a linter passes, and has a rollback that redeploys `latest`. The release also removes a database column the old version reads. Identify four material defects and outline the safer release. Give two checks that would prove what shipped and that it is working. UI extension. A checkout submits a request and receives a network timeout. Describe what the client should show, how it can look up the result, and which server-side protection lets it retry safely.

### E. Data Scientist and ML · 25 minutes

A fictional churn dataset has 10,000 customer snapshots and a 6% churn rate. The model uses a field populated when a customer cancels, normalizes the full dataset before splitting, and randomly splits rows even though the same account appears multiple times. It reports 94% test accuracy and claims deployment readiness. Explain each methodological defect, name a better evaluation plan, and state one reason precision and recall both matter. SQL extension. With `customers(id)` and `payments(customer_id, amount, status)`, write a query that returns every customer and their sum of settled payments, with zero for a customer without any.

## Answer key and readiness rubric

**A.** B is the better source-grounded answer, although it does not follow the two-bullet instruction. A invents phone cancellation, incorrectly includes the fee, and also misses the format. A compliant rewrite is “• Open Bookings in your account and cancel the reservation. • Since you canceled 52 hours before arrival, you’ll get an $80 refund. The $5 booking fee is excluded.”

**B.** Inserting before checking permits a self-pair. With `[3]` and target `6`, the function returns `(0, 0)`. Overwriting an earlier duplicate loses the tie-break. With `[1, 1, 4]` and target `5`, it returns `(1, 2)` instead of `(0, 2)`. Check first and keep the earliest index for each value.

```python
def first_pair(values, target):
    earliest = {}
    for j, value in enumerate(values):
        complement = target - value
        if complement in earliest:
            return earliest[complement], j
        earliest.setdefault(value, j)
    return None
```

Expected O(n) time and O(n) extra space. Check empty input, `[3]` with target `6` → `None`, `[3, 3]` with target `6` → `(0, 1)`, `[1, 1, 4]` with target `5` → `(0, 2)`, `[-3, 0, 3]` with target `0` → `(0, 2)`, and `[5, 1, 4, 0]` with target `5` → `(1, 2)` to verify the smallest `j` rule. An atomic database constraint scoped to the relevant user or tenant and key can prevent duplicate creation, coupled with a transaction and a stored result or status. A matching payload can get the original result, and a different payload should receive a conflict. Fire two concurrent same-key requests and verify one durable order. Also test reused keys with different payloads.

**C.** Budget $30,000, actual $29,700, total $300 unfavorable. Volume contributes −$3,000 and price +$2,700. Explain what the bridge shows and say the cause needs evidence. For valuation, NOPAT is $18m and FCFF is $18m + $6m − $10m − $5m = **$9m**. Adding the increase gives $19m and overstates FCFF by $10m. The simplified EV is $9m ÷ (10% − 2%) = **$112.5m**. Equity value is $112.5m − $30m + $8m = **$90.5m**. Stress-test WACC, perpetual growth and the consistency of reinvestment and working-capital assumptions. Base DSCR is **1.20×**, exactly at the stated floor. Downside NOI is $612,000 and DSCR is **1.02×**, below the floor.

**D.** Mutable tags obscure what shipped, owner access is excessive, linting misses behavior, redeploying the same mutable tag does not identify the last good version, and the schema change breaks the old application. Deploy a pinned artifact produced by passing tests with a narrowly scoped identity. Use backward-compatible schema changes and monitor a staged release. Keep a known-good image and verify data compatibility before rollback. Check the deployed digest and run an end-to-end booking smoke test. A timed-out checkout can show “checking order status,” look up by order or idempotency key, and retry with the same key if the server supports atomic deduplication.

**E.** The cancellation field is unavailable at the prediction point, so it leaks the outcome. Fitting preprocessing before splitting leaks holdout information. Random snapshot splits can put the same account in both sets and may leak future conditions. Use a holdout aligned with deployment timing and the prediction target, with account grouping where appropriate and explicit overlap checks. Fit preprocessing only on training data. A model predicting “no churn” for everyone also reaches 94% accuracy, so accuracy alone cannot establish lift. Precision helps control wasted outreach and recall helps quantify churners missed. Report both with the threshold, baseline, and outcome window.

```sql
SELECT c.id, COALESCE(SUM(p.amount), 0) AS settled_amount
FROM customers AS c
LEFT JOIN payments AS p
  ON p.customer_id = c.id AND p.status = 'settled'
GROUP BY c.id;
```

Filtering settled status in the `ON` condition preserves customers without qualifying payments. The example assumes one row per payment. If joining through another one-to-many table, check for duplicate contributions before aggregating.

**Self-score each drill out of 10** — correctness 4, complete instruction coverage 2, evidence or tests 2, clarity 2. Aim for at least **8/10 on two new independent drills** in the target area, with no critical correctness errors. Examples of critical errors include an unsupported claim that changes the conclusion, a broken working-capital sign, returning the same index twice, a security bypass, or data leakage. This is a personal practice threshold. The company’s pass threshold is unpublished.
